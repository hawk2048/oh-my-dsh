# oh-my-dsh · First-principles 第一性原理

**往下拆**而不是横着看：把「大家都这么做」「以前一直如此」的惯性假设剥掉，还原到当前场景下**可验证的基本事实**，再从事实层重建方案。对应 OMC 的 `first-principles` 提示词触发模式。

## 何时用

- 方案看起来「合理」只因它是惯例——要判断惯例在当前场景还成不成立。
- 成本/性能/架构估算失真，怀疑其中混入了过时假设。
- 用户说「从头推导」「别按惯例」「还原到底」。
- 重大决策前的约束审计：哪些是真约束（物理、协议、生态），哪些只是历史包袱。

## 推理纪律

1. **列事实清单**：把当前方案的结论依赖拆成一条条「事实」。**每条事实必须落到可验证来源**——代码行、官方文档、实测数据、协议规范。给不出来源的不算事实。
2. **分离假设**：从事实之外的部分提取依赖假设，逐条标注类型：`[实测]` `[官方文档]` `[行业惯例]` `[个人经验]` `[猜测]`。**惯例和经验是最可能过时的两类**，重点审。
3. **逐条证伪**：对每条假设问「在当前场景它还成立吗」。能用便宜实验/测量验证的，先验证再推理——一次 `time`、一次 benchmark、一次小流量，都优于十段推演。
4. **从事实层重建**：只基于保留的事实推导新方案。新方案里每引入一个假设，都要说明为什么它拆不掉。
5. **怀疑者检验**：对每条自称「基本事实」的条目再问一次——「如果我是质疑者，我怎样验证它？」答不出验证方法的，降级为假设。

## 与其它模式的关系

- `omd-deep-analyze` 是**横向**多角度看现状；本模式是**纵向**还原拆假设。先跑本模式确定「哪些约束是真的」，再转 deep-analyze 做方案权衡。
- `omd-ultrathink` 是纯思考；本模式的产出必须落在可验证证据上，不允许纯推演收尾。
- 重建出的方案转 `omd-plan` 落地；需求本身没问清先 `omd-deep-interview`。

## 收尾：HUD

用 `omd-hud` 输出三张表：

- **事实表**：事实 / 来源（文件：行、文档、实测）/ 验证方式。
- **假设证伪表**：假设 / 类型 / 判定（保留·已验证｜拆除·已证伪｜保留·拆不掉）/ 对方案的影响。
- **重建方案**：只列事实层支持的结论，标注剩余假设数量。

让「哪些是事实、哪些拆掉了、方案靠什么站住」一眼可见。

## 反模式

- **别伪造公理**：装作「从零推导」实则把猜测当事实。给不出验证来源的「事实」等价于假设，必须降级。
- **别为拆而拆**：拆除有成本。真正成立的约束（协议兼容、生态依赖、安全边界、团队认知成本）是合理权衡对象，不是惯性——保留它们并说明理由。
- **别当修辞用**：「第一性原理」不是否定一切工程折中的大棒。拆解深度应与决策权重成正比——改一行代码不值得还原到晶体管。
- **别跳过验证**：能用一次实验证伪的假设，推演一百句也不如跑一次。
