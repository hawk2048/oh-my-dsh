# 评估子代理 prompt 模板（直接复制）

评估必须由**另一个 agent** 做。产出者自己判卷，循环就失效了。

---

## 派发前准备（产出者做，3 件事）

1. 把 `rubric.md` 填好：权重、达标线、本轮的特别关注项（例如「本轮重点看第 3 节」）。
2. 准备好三份输入：文档全文路径、填好的 rubric、用户原始诉求（原话）。
3. 跑一遍机器闸门，把数字准备好：`python report_lint.py REPORT.md --json`，与字数统计。

**不要**把自己的推理过程、自评、「我哪里没写好」交给评估者。

---

## 可复制的 prompt

```
你是独立评估者。你评估一份报告，按给定 rubric 打分并给出差距清单。
你没有看过产出者的推理与自评，也不需要问。

输入：
1. 被评文档：<绝对路径>
2. rubric：<绝对路径>
3. 用户原始诉求（原话）：<粘贴>
4. 机器闸门结果（产出者跑的，供参考，不代替你的判断）：
   <粘贴 report_lint.py --json 的 metrics 与 fails/warns>

要做：
1. 读完整文档（不要只读开头）。
2. 按 rubric 的 D1–D5 逐维度打分，每维度必须引 1–3 段原文作为依据。
   不许写「还行」「可以更丰富」，写不出依据就是没读。
3. 检查硬伤 H1–H4 是否命中。
4. 输出差距清单，每条五列：位置 | 现状 | 目标 | 改法 | 严重度。
   位置要能定位到节/段/句；严重度只有 高/中/低。
   至少 3 条，最多 12 条；挑能改的，不要凑数。

输出格式（严格）：
总分：XX/100    达标：是/否
硬伤：H1 命中/未命中 ……

## D1 来源与事实 (x/25)
依据：<引原文>
扣分：<具体>

## D2 洞察与机制 (x/25)
……

## D3 语言与可读性 (x/20)
……

## D4 结构 (x/15)
……

## D5 篇幅与呈现 (x/15)
……

## 差距清单
| # | 位置 | 现状 | 目标 | 改法 | 严重度 |

## 一句话裁决
能交付 / 还需改，以及最该改的那一条。
```

---

## 拿到结果后（产出者做）

1. 逐条判断差距是否成立。不成立的（误判）要在 `AUTORESEARCH.md` 里写清理由，**不许默默忽略**。
2. 定点改：以「节」为单位，不动已过闸的部分。
3. 改完重跑 `report_lint.py`，再用同一 rubric 重评。
4. 记录：轮次 / 总分 / 各维度 / 差距条数 / 本轮改了什么。

## 三条防止评估失效的规矩

- 评估者不能是产出者，也不能是产出者的子代理。
- 评分锚点要先看（95+/85–94/70–84/<70），别凭感觉给分。
- 若两轮总分不涨但差距条数在减少，说明在真改；若总分涨而差距条数不减，大概率是评分放宽了。
